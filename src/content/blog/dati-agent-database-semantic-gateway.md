在构建基于 LLM 的企业级 Agent 时，最核心且最具挑战的环节之一就是**如何让模型正确、安全地读写企业业务数据库**。

传统的做法通常依赖于简单的 Text-to-SQL Prompt 拼接，往往面临以下痛点：
1. **业务黑话与缩写**：表名和字段命名不够直观，模型难以理解业务术语。
2. **多数据库异构**：MySQL、ClickHouse、PostgreSQL 等方言各异。
3. **权限与安全隔离**：直接暴露 SQL 执行环境具有极高注入与误删风险。

为此我发起了开源项目 **DatI (Data Intelligence)**。

```text
┌────────────────────┐  ┌────────────────────┐
│  User A: OpenCode  │  │  User B: WorkBuddy │
└──────────┬─────────┘  └──────────┬─────────┘
           └───────────────────────┼───────────────────────┘
                                   ▼ MCP (Streamable HTTP)
┌─────────────────────────────── DatI ───────────────────────────────┐
│       Semantic       │       Security       │        Tools         │
└──────────────────────────────────┬─────────────────────────────────┘
                                   ▼
┌────────────────────────────────────────────────────────────────────┐
│     MySQL      │   PostgreSQL    │   ClickHouse   │     Doris      │
└────────────────────────────────────────────────────────────────────┘
```

### 核心设计哲学

1. **协议标准化（Model Context Protocol）**  
   全面拥抱 Anthropic 推出的 MCP 协议（支持 Streamable HTTP），让任意 MCP 客户端（如 Claude Desktop、Antigravity、VS Code 等）都可以一键挂载数据源工具。

2. **语义元数据下沉**  
   不需要复杂的训练微调，只需在管理端为表、列配置业务别名与枚举字典，结合轻量向量语义检索，让 Agent 自主探查数据结构。

3. **预置工具 + 参数化 SQL 双轨制**  
   对高危操作提供参数化模板约束；对分析型只读查询提供带上限的探查工具，兼顾灵活性与安全性。
